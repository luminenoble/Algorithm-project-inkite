## 实现要点

### `OrigamiService`（lib/services/origami_service.dart）

- 单例 `OrigamiService.instance`。
- `generate({ challengeId, style?, live? }) → OrigamiResult` 包装 `FirebaseFunctions.instanceFor(region: 'asia-east1').httpsCallable('generateOrigami').call(...)`。
- region 写死 `asia-east1`，与 `functions/src/index.ts` 的 `setGlobalOptions({ region: 'asia-east1' })` 对齐——不一致会跨区调用导致延迟翻倍 + Functions 找不到。
- `OrigamiResult` 是简单数据类（`origamiId / imageUrl / style / source`），方便上层接 SnackBar / 跳画廊。

### 编辑器挂接（story_editor_screen.dart `_submit`）

```dart
final triggerOrigami = publish &&
    _mode == StoryMode.official &&
    _challengeId != null;

if (triggerOrigami) {
  OrigamiService.instance.generate(challengeId: _challengeId!).then(
    (r) => debugPrint('[T4.2] origami unlocked: ${r.origamiId}'),
    onError: (e) => debugPrint('[T4.2] origami generation failed: $e'),
  );
}

// 紧接着 SnackBar + 跳回写作落地页（不等 CF）
```

**触发条件**：

| 条件 | 原因 |
|------|------|
| `publish == true` | 草稿不发折纸（schema 防刷会拒，也省一次 CF） |
| `_mode == StoryMode.official` | 自由 / 日记 / 随笔 / 同人都不发折纸，仅官方挑战 |
| `_challengeId != null` | CF 防刷的查询参数 |

编辑模式也会触发——CF 幂等保证「已发过这个挑战的折纸」不会刷第二件，所以即使用户重新发布同一挑战 story，CF 内部直接 hit idempotent。

### Fire-and-forget 而非 await

不阻塞用户跳页：
- 发布主流程 `await create()` / `await update()` 已完成，SnackBar 立刻出
- `OrigamiService.generate()` 不 await，`.then/.onError` 处理结果
- CF 1–3 秒后写完 `origami/{id}` → 用户切到展览厅就能看到，由 `streamMine` 自动响应
- 失败仅 `debugPrint` 日志，不打扰用户——用户去画廊看一眼就知道有没有

**为什么不 await + 显示 Loading**：演示视频节奏看：「发布→跳页」一气呵成更利落，3 秒的等待不值得做一个 Loading。

### SnackBar 文案

| 情形 | 文案 |
|------|------|
| 发布官方挑战 | `已发布到广场 · 折纸藏品已发放，去展览厅看看` |
| 发布非官方 | `已发布到广场` |
| 保存草稿 | `草稿已保存` |

「已发放」是乐观文案——CF 还在跑时就这么说。失败概率极低（CF 防刷过了 = 池有图 = 一定能发）。

## 设计取舍

- **不引入 progress 指示器 / 折纸生成专屏**：等折纸的 1–3 秒不值得做 UI 投资。展览厅 Stream 自动推送 = 演示视角就是「发布→去画廊→已有新折纸」。
- **不缓存 `OrigamiResult` 到本地**：reactive 数据流走 Firestore Stream，CF 写完客户端自动同步。本地状态变成多了一份「最近一次结果」很容易和 Firestore 状态漂移。
- **`live: false` 默认**：T4.2 平时调用走预生成池零成本；演示当天若想现场展示「实拍」环节，临时改成 `live: true`（或加 UI 切换按钮，单人 demo 不做）。
- **region 写死字符串而非读 firebase_options**：`firebase_options.dart` 是 FlutterFire 平台配置，不含 Functions region 概念。后续如果加多区域部署再抽 const。
- **fire-and-forget 的错误吞没**：故意。CF 失败的演示价值低于 fluency 损失。如要查 → console + `firebase functions:log --only generateOrigami`。
