## 实现要点

### 解锁状态来源

- 唯一事实来源：`users/{uid}.unlocks.rooms` 字符串数组。
- 房间 ID：`zen_garden`（在 `ZenGardenScreen.roomId` 常量统一管理）。
- 字段由 T1.8c 触发器维护（「完成首个官方挑战时 push 进 ID」），**T1.8c 当前未实施**——演示前在 Console 改字段验证两态，或等 T1.8c 落地后自动生效。

### 房间入口卡 (`RoomEntryCard`)

- `StreamBuilder<UserProfile?>` 吃 `UserRepository.watchProfile(uid)`。
- 已解锁：金箔 `#B8893A` 描边加粗 + 朱砂淡底图标 + 「已解锁」金箔小徽章；点击进入房间。
- 未解锁：浅灰描边 + 锁形图标 + 「完成首个官方挑战即可解锁」；点击同样允许进入（详情屏内部渲染锁定态，避免「卡在路由外不让进」对解锁时机抢的恶心体验）。

### 房间屏 (`ZenGardenScreen`)

- 自身再读一次 `watchProfile` 判定解锁态，**不依赖路由守卫**——T1.8c 实施后状态变化可即时刷新，无需重新跳转。
- 解锁态 (`_UnlockedView`)：渐变纸面背景 + 金箔描边的房间标识卡 + 一段禅意短句 + 「完整动效将在 R12 之后补齐」的告知条。`fronted-design.md` §9 设想的沙纹 / 飘落折纸叶动效本版仅静态。
- 锁定态 (`_LockedView`)：大锁图标 + 「禅意花园未解锁」+ 解锁条件。

### 展览厅主屏改造

- 原 `Scaffold > Body > _OrigamiGrid` 改为 `CustomScrollView`：
  - `SliverToBoxAdapter` 挂 `RoomEntryCard`
  - `SliverToBoxAdapter` 挂 `_SectionLabel('折纸藏品')`
  - `_OrigamiSliver` 网格部分（用 `SliverGrid.builder`，空 / waiting / error 三态用 `SliverFillRemaining`）

### 路由

- `/gallery/room/zen-garden` 挂在 `/gallery` 下，留在 ShellRoute 内底部 Tab 仍可见。
- 回退用 `context.go('/gallery')`，与 T3 详情页同款约定。

## 设计取舍

- **房间屏自身二次判定解锁态**：而不是路由守卫拦截。解锁状态在演示当下可能瞬间翻 true，路由级硬拦容易把用户卡在 `/gallery` 不动；屏内判定既支持「点进来后实时解锁」也省一层 redirect 逻辑。
- **静态美术 + 文案告知动效未做**：避免未做的动效成为「看起来缺失」的体验创伤，明确告知比留白更友好。`fronted-design.md` §9 的飘落折纸叶 / 沙纹光影留到 R12 之后。
- **房间 ID 常量集中在房间屏**：`ZenGardenScreen.roomId = 'zen_garden'`，入口卡引用同一常量；后续如再加房间（如『水墨阁』），照此一房间一屏 + 一常量即可，不会散落。
- **不改 `users.unlocks`**：客户端只读，T1.10a 收紧规则后字段级 CF-only。任何「测试解锁」都在 Console 手工改字段。
