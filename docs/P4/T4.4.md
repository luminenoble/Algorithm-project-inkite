## 实现要点

### 解锁监听 (`MagicInkGate`)

- 中间层小组件：内部 `watchProfile` 读 `unlocks.magicInk`，未解锁 → `SizedBox.shrink`；解锁 → 调用方提供的 `builder` 渲染对应 UI。
- 抽出这层是为了让 gallery / editor 零成本接入，且把 Stream 订阅集中——同页两个金箔元素也是两次订阅，但 Firestore 客户端会自动复用同一 `users/{uid}` 文档监听，无额外网络代价。

### 视觉形态

- **`MagicInkBanner`**（展览厅横幅）：金箔渐变底（左右淡渐变 `0x1F → 0x0F`）+ 金箔边 + `Icons.auto_fix_high` + 「魔法墨水已激活」+ 副文「藏品边缘已镶金箔」。横向铺满，置于房间入口卡之上。
- **`MagicInkChip`**（编辑器徽章）：紧凑版小徽章，置于编辑器 AppBar `actions` 区第一个，与「保存草稿」/「发布」并列。

### 联动 OrigamiCard 边框

- `_OrigamiSliver` 内多包一层 `watchProfile` 读 `magicInk`，下传给 `_OrigamiInner` → `OrigamiCard.goldEdge`。
- 解锁瞬间所有藏品卡边框由浅灰 `#E7E0D0` 变金箔 `#B8893A`（T4.1 已预留这个钩子）。

### 不写 unlocks

- 客户端**只读** `users.unlocks`（CLAUDE.md §3、schema 安全规则）。任何「测试解锁」都在 Console 手工改字段；T1.10a 收紧规则后字段级 CF-only，前端误写会被拒。

## 设计取舍

- **`MagicInkGate` 抽中间层 vs 散在每页里写 StreamBuilder**：抽出来后调用方一行 `MagicInkBanner()` 就接入；解锁判定永远走 `unlocks.magicInk ?? false` 这条单一路径，避免后续多处复制粘贴写错条件。
- **静态横幅 + 颜色切换 vs Lottie 金箔展开**：`fronted-design.md` §8.3 设想 `unlock_gold.json` Lottie 动效 + 笔触晕染。当前 Lottie 体系未引入（pubspec 还没加 `lottie`），用静态金箔渐变 + 边框颜色切换是最低成本的解锁信号；同时设计文档承诺的「视觉彩蛋」语义已满足。
- **编辑器只挂徽章，不改笔触特效**：真正的笔触晕染 / 渐变需要自定义 `TextField` 绘制层，复杂度远超本任务 P2 范围。徽章是「解锁可见信号」，足以承载演示叙事。
- **goldEdge 钩子在 T4.1 就预留**：T4.4 这里只是把它接到 magicInk 上，零侵入式联动，符合「视觉投资分层」的设计原则。

## 与设计规格的差距

`docs/fronted-design.md` §2.2 设想 `unlock_gold.json` 金箔从锁形展开的解锁动效；§5.5 / §8.3 设想编辑器正文笔触在 magicInk 解锁后启用 `strokeEffect`（晕染 / 渐变）。本任务仅做静态信号（横幅 + 徽章 + 边框颜色）。完整动效与笔触特效是 R12 之后的视觉投资，UI 替换不会破坏数据接口。
