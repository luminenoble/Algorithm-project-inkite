## 仓库内已交付

### 1. Flutter 工程初始化

```bash
flutter create app-storage \
  --project-name=inkite \
  --org=com.inkite \
  --platforms=android \
  --description="Inkite — creative writing meets community sharing"
```

- Dart 包名：`inkite`
- 工程目录：`app-storage/`（仓库根下）
- 仅生成 Android 平台脚手架；iOS/macOS/Web/Linux/Windows 当前 demo 不需要

### 2. 包名对齐修复

`flutter create` 默认 Android 包名为 `<org>.<project_name>` = `com.inkite.inkite`，与 Firebase Console 注册的 `com.inkite.app` 不匹配。已统一改为 `com.inkite.app`：

| 修改点 | 旧值 | 新值 |
|--------|------|------|
| `android/app/build.gradle.kts` `namespace` | `com.inkite.inkite` | `com.inkite.app` |
| `android/app/build.gradle.kts` `applicationId` | `com.inkite.inkite` | `com.inkite.app` |
| `MainActivity.kt` 的 `package` 声明与目录路径 | `com/inkite/inkite/` | `com/inkite/app/` |

### 3. `google-services.json` 搬迁

按 T1.1.md 规划，从仓库根目录移至 `app-storage/android/app/google-services.json`：

```bash
mv google-services.json app-storage/android/app/google-services.json
```

- `.gitignore` 第 21 行匹配全路径，已验证仍处于 ignored 状态
- 同目录新增**脱敏模板** `google-services.json.example`，供其他成员参考字段结构

### 5. `lib/` 目录约定

```
app-storage/lib/
├── main.dart                  # Firebase.initializeApp + MaterialApp.router
├── firebase_options.dart      # 占位 stub，待 flutterfire configure 覆盖
├── routing/
│   └── app_router.dart        # GoRouter + authStateChanges 路由守卫
└── features/
    ├── auth/
    │   └── login_screen.dart  # 匿名登录 + Firestore 写读探针（T1.5 替换为完整 AuthService）
    ├── shell/
    │   └── main_shell.dart    # 底部 Tab 主框架（写作/广场/展览厅/我的）
    ├── writing/               # P2 写作模块
    ├── square/                # P3 社区模块
    ├── gallery/               # P4 展览厅模块
    ├── me/                    # 我的 Tab（uid 展示 + 登出）
    └── character/             # 模块 G 嵌入位置（由 P4 接入）
```

每个 feature 目录下放一个对应 `*_screen.dart` 占位页，仅显示模块名 + 责任人标识。

### 6. `firebase_options.dart` 当前状态

stub 实现：调用 `DefaultFirebaseOptions.currentPlatform` 会抛 `UnimplementedError` 并提示运行 `flutterfire configure`。这样工程可以正常 `flutter analyze`（编译通过），但运行时会立即给出明确指引，避免出现含糊的"firebase 未初始化"错误。

### 7. 路由 + 探针

`app_router.dart` 通过 `FirebaseAuth.authStateChanges()` 桥接到 GoRouter 的 `refreshListenable`：

- 未登录 → 强制重定向到 `/login`
- 已登录 → `/login` 自动跳 `/writing`
- 主框架内 4 个 Tab 用 `ShellRoute` + `NavigationBar` 实现

`login_screen.dart` 内的"匿名登录并验证"按钮串起 T1.3 验收的端到端探针：

1. `FirebaseAuth.signInAnonymously()` → 拿到 uid
2. `Firestore.collection('_probe').doc(uid).set({...})`
3. 读回 `docRef.get()` 验证存在
4. `context.go('/writing')` 进入主框架

> `_probe` 集合用于一次性连通性验证，T1.10 收紧规则前可保留；正式收紧时同步删除该集合。

## 需 P1 手动完成的动作

### A. 生成真实 `firebase_options.dart`

```bash
cd app-storage
dart pub global activate flutterfire_cli   # 若尚未装
export PATH="$HOME/.pub-cache/bin:$PATH"
flutterfire configure
```

交互选项：
- 项目：选 `inkite-demo`
- 平台：仅勾 **Android**
- 配置文件覆盖：**Yes**

完成后会：
- 覆盖 `lib/firebase_options.dart` 为真实配置
- 同步更新 `android/app/google-services.json`（如有变化）
- 在 `android/build.gradle.kts` 与 `android/app/build.gradle.kts` 内插入 `com.google.gms.google-services` 插件声明

### B. Firestore 数据库初始模式

如果在 T1.1 创建 Firestore 时选了 **production mode**（默认 deny all），T1.3 的探针写入会被拒。两种处置：

- (推荐) Console → Firestore → Rules，临时改为：

  ```
  rules_version = '2';
  service cloud.firestore {
    match /databases/{database}/documents {
      match /{document=**} {
        allow read, write: if request.auth != null;
      }
    }
  }
  ```
  T1.4 会用正式规则覆盖。

- 或者改为 **test mode**（30 天内全开），到期前必须由 T1.4 接管。

### C. 端到端验证

```bash
cd app-storage
flutter run                # 真机或 Android 模拟器
```

操作：

1. App 启动 → 落在登录页
2. 点击"匿名登录并验证"
3. 状态文本依次显示：匿名登录中 → 写入测试文档 → 读回测试文档 → 端到端链路 OK
4. 自动跳转到 `/writing` Tab，底部 4 个 Tab 可切换
5. Firebase Console → Firestore → 验证 `_probe/{uid}` 文档已存在
