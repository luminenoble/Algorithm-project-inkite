## Firebase 套餐前置（重要变更）

> **2024-10-30 起，Google 对新建 Firebase 项目收紧了 Spark 套餐限制**：
>
> - **Cloud Functions**：自 2020-09 即要求 Blaze
> - **Cloud Storage for Firebase**：新建项目必须 Blaze 才能初始化默认 bucket
> - **Auth + Firestore**：仍可在 Spark 上跑

由于 `inkite-demo` 是 2026 年新建项目，**Day 1 即需升 Blaze**，否则 Storage 与 Functions 都无法启用。Spark 上只能先把 Auth + Firestore 跑起来，但 T1.4（Storage Rules）与 T1.7 / T1.8（Functions）会被卡住。

**风险与对策**：
- demo 流量极低，Blaze 按量计费下实际月度消耗近 0
- 升 Blaze 前**必须**先在 Google Cloud Billing 设置预算告警（步骤见下方），避免误操作或异常调用导致费用突增
- 本地开发阶段全程使用 **Firebase Emulator Suite**，不消耗云端额度

## 需 P1 在 Firebase Console 完成的动作

### 1. 创建项目

1. 打开 https://console.firebase.google.com
2. **添加项目** → 项目名 `inkite-demo`
3. 启用 Google Analytics：**否**（演示项目不需要）

### 2. 设置 Billing 预算告警（升 Blaze **之前**做）

- Google Cloud Console → Billing → Budgets & alerts
- 月度预算 **¥50** 或 **$7**
- 阈值告警：50% / 90% / 100%
- 收件邮箱：P1 + 备用

### 3. 升级到 Blaze 套餐

- 项目设置 → 用量与结算 → 修改方案 → **Blaze**
- 绑定信用卡或 Google Cloud 结算账号
- 确认上面 Step 2 的预算告警已生效

### 4. 启用服务

进入项目后依次启用，**所有服务统一选 `asia-east1`**，避免跨区延迟与额外费用：

- [x] **Authentication** → Sign-in method → 启用 **Anonymous** 与 **Email/Password**
- [x] **Firestore Database** → 创建数据库 → **Native 模式** → 区域 `asia-east1`
- [x] **Storage** → 开始使用 → 区域 `asia-east1`（需 Blaze）
- [x] **Functions** → 区域 `asia-east1`，部署延后到 T1.7/T1.8（需 Blaze）

### 5. 注册 Android App

1. 项目概览 → 添加应用 → Android
2. 包名：`com.inkite.app`
3. 下载 `google-services.json` → 当前临时放仓库根目录
4. T1.3 之后搬到 `app-storage/android/app/google-services.json`
5. 验证 gitignore：`git check-ignore -v google-services.json`（已确认）

### 6. 核对 `.firebaserc`

若实际项目 ID 不是 `inkite-demo`（如 `inkite-demo-a1b2c`），用 firebase CLI 同步：

```bash
firebase login         # WSL 无桌面用 firebase login --no-localhost
firebase use --add
```

或直接编辑 `.firebaserc` 把 `default` 改成真实 ID。
