## 维护字段（schema 对齐 `users/{uid}`）

```jsonc
{
  "stats": {
    "storiesCount": 0,        // 当前用户已发布到广场的 story 数
    "likesReceived": 0,       // 自己 story 收到的点赞总数
    "engagementScore": 0      // storiesCount*3 + likesReceived
  },
  "unlocks": {
    "magicInk": false,        // engagementScore ≥ 5 → 自动翻 true（永不翻回）
    "rooms": []               // 首次官方挑战发布 → push 'zen_garden'
  }
}
```

**所有这些字段都是 CF-only**——客户端只读，T1.4 规则强制（T1.10a 收紧后字段级校验）。

## 触发器矩阵

| 触发器 | 何时跑 | 干啥 |
|--------|--------|------|
| `onStoryCreated` | story 文档新增 | 初始化 hotScore（沿用 T1.7）；**新增**：若 `publishedToSquare==true`，作者 `stats.storiesCount +1`；若是 official，push `zen_garden` 进 `unlocks.rooms` |
| `onStoryUpdated`（新） | story 文档更新 | 监控 `publishedToSquare` 翻转。草稿→发布 = +1（首官方挑战时 push room）；发布→撤回 = -1（room 不撤回） |
| `onStoryDeleted`（新） | story 文档被删 | 若被删时是「已发布」状态，作者 `storiesCount -1` |
| `onLikeCreated` | 点赞子集合新增 | 维护父 story `likeCount +1`（沿用 T1.7）；**新增**：作者 `likesReceived +1`（防自赞） |
| `onLikeDeleted` | 点赞子集合删 | 父 story `likeCount -1`（沿用）；**新增**：作者 `likesReceived -1` |
| `onCommentCreated` | 评论子集合新增 | 维护父 story `commentCount +1`（沿用 T1.7，与 user.stats 无关） |
| `onCommentDeleted` | 评论子集合删 | 同上 `commentCount -1` |

> 评论不进 engagementScore——只用「写故事 + 收赞」两个原始信号，避免演示中评论刷分。如果觉得分数过严，把公式改成 `storiesCount*3 + likesReceived + commentsReceived` 即可（要的话再加一个 author 的 commentsReceived 字段，schema 当前没；改 schema 是 P0 决定，先不做）。

## `applyUserDelta` 设计

```typescript
export async function applyUserDelta(uid, {
  storiesDelta?, likesDelta?, unlockRoom?
}) {
  await db.runTransaction(async (tx) => {
    const snap = await tx.get(userRef);
    if (!snap.exists) { logger.warn(...); return; }
    const newStoriesCount = Math.max(0, ... + storiesDelta);
    const newLikesReceived = Math.max(0, ... + likesDelta);
    const newEngagement = newStoriesCount*3 + newLikesReceived;
    const update = {
      'stats.storiesCount': newStoriesCount,
      'stats.likesReceived': newLikesReceived,
      'stats.engagementScore': newEngagement,
    };
    if (newEngagement >= MAGIC_INK_THRESHOLD && !unlocks.magicInk) {
      update['unlocks.magicInk'] = true;
    }
    if (unlockRoom) {
      update['unlocks.rooms'] = FieldValue.arrayUnion(unlockRoom);
    }
    tx.update(userRef, update);
  });
}
```

要点：
- **事务 read-modify-write**：保护并发点赞 / 发文导致计数漂移
- **`Math.max(0, ...)`**：防计数跑负（极端时序保护，与 T1.7 风格对齐）
- **`magicInk` 单向翻转**：跨阈值时翻 true，之后即使 stats 下降也保留 true（设计上「解锁了就是解锁了」）
- **`arrayUnion`**：幂等，重复 push `zen_garden` 无副作用
- **失败仅 log**：上层触发器有自动重试，不抛错避免拖累链路

## 阈值与房间 ID

```typescript
const MAGIC_INK_THRESHOLD = 5;
export const ZEN_GARDEN_ROOM_ID = "zen_garden";
```

- 阈值 5 → 「2 篇故事」或「1 篇 + 2 赞」即触发。Demo 期容易跨过，不会让魔法墨水视觉一直锁着。
- `ZEN_GARDEN_ROOM_ID` 必须与客户端 `ZenGardenScreen.roomId` / `RoomEntryCard` 引用的 `zen_garden` 字符串完全一致——改一处需同步两边。

## 验收清单

> 前提：T4.2 已联通（让你不用手工调 generateOrigami 也能触发链路）。

- [ ] **storiesCount**：发一篇新 story 到广场（任意 mode）→ 1-2 秒内「我的」页面 `storiesCount` +1
- [ ] **官方挑战首发解锁禅意花园**：发第一篇 official + published → 1-2 秒后展览厅顶部「禅意花园」入口卡变金箔描边 + 「已解锁」徽章
- [ ] **再发第二篇官方**：不再额外 push（arrayUnion 幂等），但 storiesCount 继续 +1
- [ ] **likesReceived**：让另一个账号给你的 story 点赞 → 你的 `likesReceived` +1
- [ ] **engagementScore**：自动重算（storiesCount*3 + likesReceived）
- [ ] **magicInk 阈值翻转**：engagement ≥ 5 后展览厅顶部出金箔横幅 + 折纸卡片金箔边 + 编辑器 AppBar 金徽章
- [ ] **撤回不撤奖**：把已发布 story 改回草稿 → storiesCount -1，但已解锁的 `zen_garden` / `magicInk` 保留
- [ ] **删 story**：删一篇已发布 story → storiesCount -1
- [ ] **防自赞**：自己给自己点赞（先解掉 T1.4 规则）→ likesReceived 不变（防御性 skip 日志 `self-like detected`）

## 排错速查

| 症状 | 可能原因 |
|------|----------|
| 发故事后 storiesCount 不动 | 1. 触发器未 redeploy；2. `users/{uid}` 文档不存在（T1.5 首登时建的，老账号可能缺）；3. 看日志 `[userStats] user xxx missing` |
| likesReceived 不动 | story 的 `authorId` 字段为空（老数据 / 手工 fake 时漏填） |
| magicInk 没自动 true | engagementScore 真的够 5 吗？看 `users/{uid}.stats.engagementScore` 实际值 |
| 撤回后 storiesCount 变负 | 不可能，`Math.max(0, ...)` 守底；若真见到，检查多个触发器是不是同时 fire |
| zen_garden 没解锁 | 故事真是 `mode='official' && publishedToSquare==true` 吗？fake 数据时 mode 是 string `'official'` 而非 enum，需精确匹配 |

## 设计取舍

- **拆 `userStats.ts`**：所有 user.stats / unlocks 改动经一个入口，未来加阈值 / 加房间不用动 5 个触发器。
- **`onStoryUpdated` 监控发布字段而非每次 update 都重算**：避免编辑标题正文也触发计数变化。`before.publishedToSquare === after.publishedToSquare` 时直接 return。
- **撤回不撤奖（已解锁不回滚）**：游戏化心理学共识——「拿到的勋章不能被剥夺」。Schema 中 `unlocks.rooms` / `unlocks.magicInk` 没有「撤销」语义。
- **commentCount 不入 engagement**：避免演示中刷评论刷分。原始信号只用「我写了」+ 「别人赞了我」，更接近「内容创造者」的画像。
- **`getStorage` 在 like 触发器里多读 story 一次**：是为了拿 `authorId`。本可以把 authorId 冗余进 like 文档，但那要改 schema + 改前端写入。多读一次 doc 在 demo 体量下成本忽略。
