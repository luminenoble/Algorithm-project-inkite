## 范围

封装稳定的 `AuthService` 与 `users/{uid}` 初始化逻辑，把"取 `uid`、监听登录态、首次登录写档案"三件事下沉到一处，让 P2/P3/P4 不必再直接接触 `FirebaseAuth`。同时把 T1.3 的占位登录页换成可演示的真账号流程（匿名 + 邮箱/密码两条线）。

**不包含**：

- 数据访问层 Repository 全集（T1.6 接手 `stories` / `comments` / `likes` 等）
- 第三方 OAuth（Windows 端 `firebase_auth` 不支持，已在范围锁定中放弃）
- `users.stats.*` / `users.unlocks.*` 的字段级 CF-only 安全约束（T1.10 收紧）
- 头像上传 / `photoURL` 写入（客户端不直接调 `firebase_storage`，留给后续）
- 邮箱验证 / 密码重置链路（demo 不展示，留作可选项）

## 设计要点

### 1. 单例 + 静态访问

```dart
AuthService.instance
UserRepository.instance
```

P2/P3/P4 在自己模块拿 `uid` 的标准写法：

```dart
final uid = AuthService.instance.currentUid;
if (uid == null) return; // 路由守卫已挡掉，这里仅作防御
```

不引入 Provider / Riverpod / GetIt 等 DI 框架——demo 周期内单例足够清晰，避免选型分叉。

### 2. 启用的登录方式

| 方式 | 用途 | Console 启用项 |
|------|------|----------------|
| 匿名（Anonymous） | T1.3 已用；演示视频里"游客试玩"路径 | Anonymous |
| 邮箱 + 密码 | 正式账号；演示视频里"注册-登录-发布"主链路 | Email/Password |

**Windows 端校验过的能力**：T1.3 已确认匿名登录走 REST 通道成功；邮箱/密码同样走 Identity Toolkit REST，无平台差异。

### 3. 首次登录写 `users/{uid}` 初始档案

策略：在 `AuthService` 每条登录路径成功后调用 `_ensureProfile(uid)`，逻辑为"`get` 一次，不存在才 `set`"。**不使用** `set(merge: true)` 兜底——避免后续 Functions 改的 `stats.*` 被客户端再次登录时回填覆盖。

字段初值（与 `docs/schema-design/design.md §1` 完全对齐）：

| 字段 | 初始值 | 备注 |
|------|--------|------|
| `displayName` | 邮箱前缀（`a@b.c` → `a`）；匿名用户 → `Guest-<uid 前 6 位>` | 客户端可改 |
| `photoURL` | `null` | 头像上传不在 T1.5 范围 |
| `createdAt` | `FieldValue.serverTimestamp()` | 服务端时间 |
| `stats.storiesCount` | `0` | CF 触发器维护 |
| `stats.likesReceived` | `0` | CF 触发器维护 |
| `stats.engagementScore` | `0` | CF 触发器维护 |
| `unlocks.magicInk` | `false` | CF 在解锁条件达成时改 |
| `unlocks.rooms` | `[]` | 同上 |

> 当前 T1.4 dev 规则允许 owner 写整个 user 文档（含 `stats` / `unlocks`），所以客户端首次 `set` 这些字段不会被拒。T1.10 收紧时会把 `stats.*` / `unlocks.*` 改为 CF-only，那时初始化流程要么改走 CF（注册触发器），要么继续允许 `create` 阶段一次性写入零值——T1.10 决定。

### 4. AuthService 公共 API（冻结给 P2/P3/P4）

```dart
class AuthService {
  static AuthService get instance;

  // 当前态
  User? get currentUser;          // FirebaseAuth.currentUser 透传
  String? get currentUid;         // currentUser?.uid 便捷封装
  Stream<User?> get authStateChanges;  // 路由 / UI 监听用

  // 登录路径
  Future<UserCredential> signInAnonymously();
  Future<UserCredential> signInWithEmail({required String email, required String password});
  Future<UserCredential> signUp({required String email, required String password, String? displayName});

  // 登出
  Future<void> signOut();
}
```

所有 `signXxx` / `signUp` 在底层 Firebase 调用成功后会 **同步等待** `_ensureProfile(uid)` 完成才返回——保证调用方拿到 `UserCredential` 时，`users/{uid}` 必然存在。

`FirebaseAuthException` 不在 AuthService 内吞掉，原样 rethrow，由 UI 层负责把 `error.code` 翻译成中文提示（见 `login_screen.dart` 的 `_translateAuthError`）。

### 5. UserRepository 公共 API（同步冻结）

```dart
class UserRepository {
  static UserRepository get instance;

  Future<UserProfile?> getProfile(String uid);          // 一次性读
  Stream<UserProfile?> watchProfile(String uid);        // 实时监听
  Future<void> updateDisplayName(String uid, String name);  // 后续昵称编辑用
}
```

> P4 后续在展览厅展示"已解锁的主题房间"时直接 `watchProfile(uid)` 取 `profile.unlocks.rooms` 即可。

### 6. 路由守卫改造

T1.3 的 `_AuthRefresh` 已经接了 `FirebaseAuth.instance.authStateChanges`，本次把它改为依赖 `AuthService.instance.authStateChanges`，语义不变但收口到 AuthService。守卫规则保持：

- 未登录 + 访问非 `/login` → 跳 `/login`
- 已登录 + 访问 `/login` → 跳 `/writing`

### 7. 登录页 UI 设计

布局上保留 T1.3 的"中央卡片"风格，三个入口并列：

1. **登录**：邮箱 + 密码，调 `signInWithEmail`
2. **注册**：邮箱 + 密码 + 可选昵称，调 `signUp`；成功后自动登录
3. **匿名试玩**：保留 T1.3 的"匿名登录"按钮，调 `signInAnonymously`

切换登录/注册用 `SegmentedButton`；表单走基础 `TextFormField` 校验（非空 + 邮箱含 `@` + 密码 ≥ 6 位，与 Firebase Auth 的硬约束对齐）。

错误展示：捕获 `FirebaseAuthException`，按 `code` 映射到中文文案（`user-not-found` / `wrong-password` / `email-already-in-use` / `weak-password` / `invalid-email` / 兜底"登录失败：<code>"），不直接抛技术错误给用户看。

## 接口契约（交付给 P2/P3/P4 的稳定面）

> 此节是 T1.5 对外承诺的最小面，**T1.6 前不变**。

### 取当前用户

```dart
import 'package:inkite/services/auth_service.dart';

final uid = AuthService.instance.currentUid;       // String?，已登录场景下非空
final user = AuthService.instance.currentUser;     // User?，需要 email/displayName 时用
```

### 监听登录态变化

```dart
StreamBuilder<User?>(
  stream: AuthService.instance.authStateChanges,
  builder: (context, snap) { ... },
);
```

### 读取用户档案

```dart
import 'package:inkite/data/repositories/user_repository.dart';

final profile = await UserRepository.instance.getProfile(uid);
// 或
StreamBuilder<UserProfile?>(
  stream: UserRepository.instance.watchProfile(uid),
  builder: (context, snap) { ... },
);
```

### `UserProfile` 字段

```dart
class UserProfile {
  final String uid;
  final String displayName;
  final String? photoURL;
  final DateTime? createdAt;
  final UserStats stats;       // storiesCount / likesReceived / engagementScore
  final UserUnlocks unlocks;   // magicInk / rooms
}
```
