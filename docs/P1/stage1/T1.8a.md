## 关键逻辑

### 1. 鉴权（与 `recompute.ts` 同款）

- 生产：`request.auth?.uid` 必须存在，否则 `unauthenticated`。
- Emulator：`FUNCTIONS_EMULATOR === 'true'` 时允许 `request.data.__testUid` 兜底。

### 2. 防刷校验

```typescript
const ownStories = await db.collection("stories")
  .where("authorId", "==", uid).get();

const hasEligible = ownStories.docs.some(d => {
  const data = d.data();
  return data.mode === "official"
    && data.challengeId === challengeId
    && data.publishedToSquare === true;
});
```

- 只用单字段 `authorId` 索引（Firestore 自动建），**不需要额外复合索引**。
- 内存里筛 `mode + challengeId + publishedToSquare`，单用户至多十几篇官方故事，零成本压力。
- 不通过 → `HttpsError('failed-precondition', '需先完成并发布该官方挑战的故事')`。

### 3. 幂等

- 查 `origami` 集合 `where('ownerId', '==', uid)` → 内存里筛 `sourceChallengeId === challengeId`。
- 命中 → 直接返回旧记录，不重新选图、不再写 Firestore。
- 演示价值：用户反复点「领折纸」按钮不会刷出多条。

### 4. 风格选择 (`pickStyle`)

- 调用方传 `style` 且在白名单（`zen` / `steampunk` / `ink`）→ 用之。
- 否则按 `challengeId` 字符串哈希稳定取一种。同挑战下不同账号选同款，便于演示对比。

### 5. 出图（预生成池路径）

```typescript
async function pickFromPool(style: Style): Promise<string> {
  const bucket = getStorage().bucket();
  const [files] = await bucket.getFiles({ prefix: `origami/pool/${style}/` });
  const candidates = files.filter(f =>
    !f.name.endsWith("/") && /\.(png|jpg|jpeg|webp)$/i.test(f.name));
  if (candidates.length === 0) {
    throw new HttpsError("failed-precondition", `素材池 origami/pool/${style}/ 为空`);
  }
  const pick = candidates[Math.floor(Math.random() * candidates.length)];
  return firebaseDownloadUrl(bucket.name, pick.name);
}
```

- **路径选择**：用 `origami/pool/{style}/` 而非 single-TODO 提议的 `origami-pool/{style}/`，是因为 `storage.rules` 已部署的公开读规则是 `match /origami/{file=**}`——直接套用，零额外规则改动。
- **URL 形式**：`https://firebasestorage.googleapis.com/v0/b/<bucket>/o/<encoded-path>?alt=media`，依赖 Storage 规则的 `allow read: if true`，**不需要 download token，也不需要 ACL makePublic**，URL 永久有效。

### 6. 写记录

```typescript
await db.collection("origami").add({
  ownerId: uid,
  imageUrl,
  style,
  sourceChallengeId: challengeId,
  source: 'pregen',          // 'flux' 时由 T1.8b 路径写
  createdAt: FieldValue.serverTimestamp(),
});
```

字段对齐 `docs/schema-design/design.md §1 origami`。

## 设计取舍

- **路径选 `origami/pool/` 而非 `origami-pool/`**：与已部署 Storage 规则吻合，免去再改 + 重部署规则。
- **下载 URL 免 token**：依赖 Storage rules 的 read-all。等 T1.10a 收紧规则到「登录用户可读」时，URL 形式需要在客户端登录态下访问；当前 demo 阶段宽松规则下都可用。
- **防刷查询走内存筛**：避免新建复合索引；单用户故事量小，全量拉一次开销远低于一次 Storage `getFiles`。
- **幂等检查走 `ownerId` 单字段**：同上，避免给 `origami` 加 `ownerId + sourceChallengeId` 复合索引。
- **`source` 字段在写入时就定型**：CF 内部知道走的是哪条路径，无需后期推断，客户端可凭 `source` 区分「预生成池 / 实拍」做不同视觉徽记（演示加分项）。
- **`style` 哈希稳定选取**：避免每次随机导致同挑战下不同账号视觉混乱，强化「官方挑战 → 对应风格」的隐喻。
