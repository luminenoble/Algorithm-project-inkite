## 实现要点

### 我的故事列表 (`MyStoriesScreen`)

- 用 `StoryRepository.streamMyStories(uid)` 拉取全部 → 内存中按 `visibility` 分流到两个 Tab：
  - **草稿** = `visibility=private`
  - **已发布** = `visibility=public`
- 每行 `_StoryRow`：标题 + 模式徽章 + 正文摘要（2 行）+ 更新时间（相对 / 绝对）+ 编辑 / 删除按钮。
- **删除**：`showDialog` 二次确认 → `StoryRepository.delete(storyId)` → SnackBar 反馈。
- **点击行 / 编辑按钮**：跳 `/writing/editor`，extra 传 `{storyId}`。

### 编辑器 edit 模式

- `extra` 含 `storyId` → 进入 edit 模式：
  - `_loading=true`，调 `StoryRepository.getById(storyId)`
  - 拿到后回填 title / body / mode / challengeId / words 到表单
  - story 不存在则 SnackBar 提示 + 退到列表页
- 提交分支：
  - 新建（无 storyId）→ `create(Story(...))`
  - 编辑（有 storyId）→ `update(storyId, title, body, visibility, publishedToSquare)`
- 返回路径：edit 模式回 `/writing/mine`，新建回 `/writing`。
- "保存草稿" / "发布" 语义与 T2.1 一致，编辑模式下可在草稿 ↔ 已发布间切换。

### 写作落地页新增"我的故事"卡片

- 展示总数（`streamMyStories` 实时计数），点击跳列表。

## 设计取舍

- **TabBar vs 分组列表**：选 TabBar，避免长列表混排时找草稿找不到；UX 更符合"内容工作流"心智。
- **不分页**：`streamMyStories` 默认 `limit=50`，单人 demo 数据量远不到上限；后续若需要无限滚动再加。
- **不引入额外的 view-only 详情屏**：列表点击直接进编辑器即可，编辑/查看共用一个 UI（节省工期）。如需阅读视角，T3.2（详情页）已涵盖。
- **删除走二次确认**：避免误删，与 `fronted-design.md` §5.3 "纸张被揉皱缩小消失"的意象对齐（动效后续补）。

## 与设计规格的差距

`docs/fronted-design.md` §5 设想"双栏文件树 + 写作/校阅模式"。T2.4 先用经典 TabBar 列表打通主路径，文件树版本作为后续打磨（属 R12 之后的视觉投资）。当前实现已覆盖所有数据语义（增删改查 + 草稿/已发布区分），切换 UI 不会破坏数据接口。
