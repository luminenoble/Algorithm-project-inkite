## 实现要点

### 组件 (`CommentSection`)

- `StatefulWidget`：持 `TextEditingController` + `_submitting` 防止重复提交。
- 顶部标题 + 输入栏（多行输入 1–4 行 + 朱砂 FilledButton 发送）。
- `StreamBuilder<List<StoryComment>>(stream: CommentRepository.watchComments(storyId))` 按时间倒序列出（最新在前）。
- 三态：waiting / error / empty 文案均贴近其他页面的口径。

### 提交流程

1. trim 文本，空 → return（按钮也不需要 disable，避免视觉跳）。
2. 未登录 → SnackBar「请先登录后再评论」。
3. `UserRepository.getProfile(uid)` 拿 `displayName` → fallback「匿名」。
4. `StoryComment(authorId: uid, authorName, text, createdAt: null, id: '')` 传给 `add`，`createdAt` 由 Repository 的 `toCreateMap` 用 `serverTimestamp` 落库；`id` 由 Firestore 自动分配，client 传空字符串占位。
5. 成功 → 清空输入框；异常 → SnackBar。

### 评论行 (`_CommentRow`)

- 圆形头像取作者名首字（含 emoji / 中文支持，用 `String.characters.first` 避免 surrogate pair 半字）。
- 时间相对格式（刚刚 / 分钟前 / 小时前 / 天前 / 绝对）。
- `isMine == true` 时右侧挂印章红 `delete_outline` 图标，弹二次确认 → `delete`；非作者不显示删除按钮，T1.10a 收紧规则后即便绕过 UI 也会被规则拒。

### 计数同步

- `commentCount` 由 T1.7 `onCommentCreated/Deleted` 触发器在父 story 上 ±1。
- 详情页 `_Stats` 行的数字靠外层 `watchById` 自动刷新，约 1–2 秒延迟。

## 设计取舍

- **倒序展示（最新在前）**：贴合「刷动态」心智，避免用户看到详情后还要滚到底才看新评论。`CommentRepository.watchComments` 默认就是 `createdAt desc`。
- **不实现「@用户」/ 楼中楼**：MVP 范围，schema 没字段支持；评论模型只有 `authorId / authorName / text / createdAt`，加层级会扯到数据模型变更（违 §0.2 接口冻结）。
- **`authorName` 在客户端拍快照而非展示时反查**：评论落库即固定，符合社区惯例（用户改昵称后旧评论保留原昵称）。
- **删除走二次确认而非滑动手势**：桌面端鼠标右滑不是原生交互，确认弹窗在 Windows + 演示视频里都更清晰。

## 与设计规格的差距
