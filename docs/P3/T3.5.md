## 实现要点

### 路由

- 挂在 `/square` 下：`GoRoute(path: 'rank', builder: ...)`，与 `story/:id` 平级。
- 入口：T3.1 SquareScreen AppBar 右上角 `emoji_events_outlined` 按钮（已在 T3.1 接好）。
- 回退用 `context.go('/square')`。

### 主体 (`RankScreen`)

- `StreamBuilder<List<Story>>` 吃 `streamSquareFeed(sort: hotScore, limit: 20)`。
- 顶部 `_RankHeader`：金箔 `emoji_events` 图标 + 「按热度排序 · 实时更新」+ 「Top 20」。
- 列表项复用 T3.1 的 `StoryCard`，传入 `rank: i + 1` 让卡片左侧渲染名次徽记（Top 3 朱砂 / 金箔 / 印章红，4–20 灰描边）。
- 空 / error / waiting 三态与广场主屏一致。

### 复用收益

- 复用 `StoryCard` 而非另写 `_RankRow`：避免一张 story 在广场 / 排行榜两套视觉漂移；T3.1 已为此预留 `rank` 入参。
- 排序索引复用 T1.4 已声明的 `visibility ASC + hotScore DESC`（T1.10a 部署），无需新加索引。

## 设计取舍

- **Top 20 而非全量**：榜单超过 20 名次徽记意义稀薄；`limit=20` 也压住单次查询读取量（Firestore 按返回文档计费，免费额度 50K reads/天，单 demo 远低）。
- **独立路由 vs Tab 内切换**：选独立路由（`/square/rank`），与广场两种排序（hotScore/newest）分清职责——广场是「浏览」，排行榜是「奖杯」。`SegmentedButton` 顶部三态会拥挤，且语义上排行榜还应有「冠军视觉」（名次徽记），与列表 chrome 不同。
- **不缓存上次榜单**：每次进重订阅 Stream，Firestore 本地缓存会优先返回上次快照，体感即时；CF 1–2 秒后再推新数据无缝刷新。
- **演示前 `recomputeHotScores`**：T1.7 触发器是「单事件局部更新」，对历史 story 不补算；演示前手调一次 `recomputeHotScores` Callable 把全表 rescore，是 T1.11 演示预案的一部分。

## 与设计规格的差距

`docs/fronted-design.md` §6.4 设想 Top 3 「折角徽标」 + 切换排序时列表错峰重排淡入。当前用矩形圆角徽记 + 标准 `ListView`，动效是 R12 之后的视觉投资。`StoryCard.rank` 入参为后续动效预留了「按名次取色 / 取动效强度」的钩子。
