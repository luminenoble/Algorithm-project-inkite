## 实现要点

### 路由

- 挂在 `/square` 下的 `routes: [GoRoute(path: 'story/:id', ...)]`，留在 ShellRoute 内底部 Tab 仍可见。
- `state.pathParameters['id']` 取 storyId 传给 `StoryDetailScreen`。
- 回退用 `context.go('/square')`，避免栈混乱。

### 主体 (`StoryDetailScreen`)

- `StreamBuilder<Story?>` 吃 `watchById(storyId)`，CF 改 `likeCount` / `commentCount` / `hotScore` 后页面自动刷新。
- 四态：waiting → loader；error → 朱砂错误文案；data == null → "故事不存在或已被删除"；正常 → `_DetailBody`。

### 详情布局 (`_DetailBody`)

- **标题区**：`official` 模式标题前挂朱砂「官方挑战」徽章；作者 + 创建时间（绝对日期 + 时分）。
- **挑战词条**（仅 official）：金箔描边卡片 Wrap 列出 `story.words`。
- **正文**：`SelectableText` 16px / 行高 1.75，贴合 `fronted-design.md` §1.2 正文规格；可选中复制。
- **计数行**：`likeCount`（朱砂心形）+ `commentCount` + `hotScore`，全部从 Stream 实时拿。
- **底部分隔**：`Divider` + 评论占位（T3.4 替换）。

## 设计取舍

- **`SelectableText` vs `Text`**：详情页是「阅读」场景，让用户能复制句段（demo 录屏好看），代价仅是右键菜单略侵入；编辑器走 `TextField` 已经可选，详情不应反退步。
- **占位评论区**：详情页 + 点赞 + 评论是三个互相依赖的功能，先把详情骨架打通便于点赞 / 评论挂载，避免一次提交里改动过多文件难以审。T3.3 接 LikeButton，T3.4 把占位 `_CommentsPlaceholder` 整体换成评论区组件。
- **`context.go('/square')` 回退**：GoRouter 在 ShellRoute 嵌套下 `pop` 行为依赖 navigator 栈深度，单人 demo 阶段固定回广场最稳，避免「从详情页 pop 出 ShellRoute」的边缘 case。
