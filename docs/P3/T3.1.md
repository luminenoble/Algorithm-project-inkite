## 实现要点

### 广场主屏 (`SquareScreen`)

- 顶部 `SegmentedButton` 切换 `SquareSort.hotScore` / `SquareSort.newest`。`hotScore` 走 `visibility ASC + hotScore DESC` 复合索引；`newest` 走 `visibility + createdAt DESC`。两条索引 T1.4 均已声明（T1.10a 部署）。
- 主体 `StreamBuilder<List<Story>>` 吃 `StoryRepository.instance.streamSquareFeed(sort: _sort)`，三态：
  - waiting → 居中 `CircularProgressIndicator`
  - error → 朱砂色文案展示 `snap.error`
  - empty → 「广场暂无故事 / 去写作 Tab 发布第一篇吧」
- AppBar 右上角 `emoji_events_outlined` 图标按钮 → 跳排行榜 `/square/rank`（T3.5）。

### 故事卡片 (`StoryCard`)

- 字段：标题（1 行 ellipsis）+ 作者（次墨色）+ 正文摘要（3 行 ellipsis）+ 点赞数 + 评论数 + 相对时间。
- `mode == official` 时右上挂朱砂「官方」徽章；`createdAt` 用相对时间格式（刚刚 / X 分钟前 / X 小时前 / X 天前 / 绝对日期）。
- 整张卡 `InkWell.onTap` 跳详情 `/square/story/:id`（T3.2）。
- **复用接口**：组件支持可选 `rank` 入参，传入时左侧加名次徽记（Top 3 朱砂 / 金箔 / 印章红），给 T3.5 排行榜复用。

### 计数字段

- `likeCount` / `commentCount` 是 CF 维护字段（`onLikeCreated` / `onCommentCreated` 触发器），客户端禁写；卡片只渲染、不计算，Stream 自动反映 1–2 秒后的变化。

## 设计取舍

- **`SegmentedButton` vs `TabBar`**：列表只有两种排序、不是两套数据源，用 SegmentedButton 更轻；保留单一 `StreamBuilder`，避免 TabBarView 内嵌两份 Stream 重复订阅。
- **卡片复用**：T3.1 / T3.5 / T2.x「我的故事」摘要的视觉差异主要在「有无名次」「点击行为」，所以 `StoryCard` 用可选 `rank` 参数承载，省去再写一套。
- **错误态**：当前直接展示 `snap.error.toString()`，方便 demo 期诊断；T1.10a 收紧规则 + 索引部署后若仍有错应在该处定位。
