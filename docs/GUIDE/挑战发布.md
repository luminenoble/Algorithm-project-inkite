# 官方挑战发布指南

本文档说明如何通过 `functions/scripts/seed_challenge.mjs` 脚本向 Firestore 写入新的官方三词挑战。脚本会自动将所有旧活跃挑战（`isActive=true`）标记为失效，再写入新挑战。

---

## 一、前置：服务账号凭证

脚本通过 Firebase Admin SDK 写入 Firestore，需要服务账号 JSON 文件。

**最简做法：将文件放在 `functions/` 目录下**

```
functions/inkite-demo-firebase-adminsdk-fbsvc-e22e9c265d.json
```

脚本会自动在 `functions/` 目录下查找文件名含 `adminsdk` 的 JSON，无需任何额外配置，直接运行即可。

> 该文件已由 `.gitignore` 的 `*adminsdk*.json` 规则排除，不会入仓。若文件丢失，前往 Firebase Console → 项目设置 → 服务账号 → 生成新私钥 重新下载，放回此处。

**其他凭证方式（可选）：**

```bash
# 方式 A：命令行参数（优先级最高）
node scripts/seed_challenge.mjs --creds /path/to/key.json --title ...

# 方式 B：环境变量
export GOOGLE_APPLICATION_CREDENTIALS=/path/to/key.json   # macOS/Linux
$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\path\to\key.json"  # PowerShell
```

## 二、网络代理（国内必看）

脚本通过 Firebase Admin SDK 直连 Google Firestore，国内网络**无法直连**，会报：

```
14 UNAVAILABLE: No connection established. Last error: connect ETIMEDOUT 142.251.x.x:443
```

加 `--proxy` 参数走代理即可：

```bash
node scripts/seed_challenge.mjs --proxy http://127.0.0.1:2334 --title "秋·霜·归" --words 秋,霜,归
```

> 也可改为设置 `https_proxy` / `grpc_proxy` 环境变量，脚本会自动读取，但 `--proxy` 最直接。

## 三、运行方式

所有命令均在 `functions/` 目录下执行：

```bash
cd functions
```

> 以下示例为简洁省略了 `--proxy`，国内环境请在每条命令里加上 `--proxy http://127.0.0.1:2334`。

### 最常用：发布新挑战（7 天有效期）

```bash
node scripts/seed_challenge.mjs --title "秋·霜·归" --words 秋,霜,归
```

输出示例：

```
✓ 已将 1 条旧挑战设为 isActive=false
    └─ abc123  "夏·风·远"  words=[夏, 风, 远]

✓ 新挑战已写入 Firestore
  id:      xyz789
  title:   秋·霜·归
  words:   [秋, 霜, 归]
  startAt: 2026-06-05T10:00:00.000Z
  endAt:   2026-06-12T10:00:00.000Z  (+7 天)
```

### 自定义有效天数

```bash
node scripts/seed_challenge.mjs --title "灯·雨·归" --words 灯,雨,归 --days 14
```

### 指定开始时间（北京时间）

```bash
node scripts/seed_challenge.mjs --title "星·海·远" --words 星,海,远 --start 2026-06-10T00:00:00+08:00
```

### 指定文档 ID（跨环境对齐时有用）

```bash
node scripts/seed_challenge.mjs --title "测试挑战" --words a,b,c --id test-challenge-01
```

### 仅停用所有活跃挑战，不创建新挑战

```bash
node scripts/seed_challenge.mjs --deactivate-only
```

## 四、参数速查

| 参数 | 必填 | 说明 | 示例 |
|------|------|------|------|
| `--title` | 是 | 挑战标题 | `"秋·霜·归"` |
| `--words` | 是 | 三个关键词，逗号分隔，不留空格 | `秋,霜,归` |
| `--days` | 否 | 有效天数，默认 `7` | `14` |
| `--start` | 否 | 开始时间，ISO 8601，默认当前时刻 | `2026-06-10T00:00:00+08:00` |
| `--id` | 否 | 自定义 Firestore 文档 ID，默认自动生成 | `qiu-shuang-2026` |
| `--deactivate-only` | 否 | 仅停用旧挑战，不写入新挑战 | （无值） |
| `--list` | 否 | 仅列出集合现状（诊断用），并复现 watchActive 查询验证索引 | （无值） |
| `--proxy` | 否 | 走代理直连 Firestore（国内必需） | `http://127.0.0.1:7890` |
| `--creds` | 否 | 指定服务账号 JSON 路径（默认自动检测） | `/path/to/key.json` |

## 五、发布后 app 不刷新（复合索引，重要）

**现象**：脚本写入新挑战成功（`--list` 能看到），但 Flutter app 里写作页仍显示旧挑战，重启、挂代理都无效。

**根因**：app 的 `ChallengeRepository.watchActive()` 查询是
`where(isActive==true) + orderBy(startAt desc)`，需要一个 `challenges` 集合的
**复合索引 `(isActive ASC, startAt DESC)`**。若该索引未部署，服务端查询会报
`9 FAILED_PRECONDITION: The query requires an index`，app 拿不到服务端结果、
只能回落本地缓存里的旧挑战（本地查询不需要索引，所以不报错、静默显示旧数据）。

**确诊**：跑 `node scripts/seed_challenge.mjs --list`，末尾「复现 watchActive 查询」
若报 `requires an index` 即是此问题。

**修复**（已在仓库 `firestore.indexes.json` 补好该索引声明，二选一部署）：

```bash
# 方式 A：CLI 部署（用仓库里的声明）
firebase deploy --only firestore:indexes

# 方式 B：点报错信息里的 https://console.firebase.google.com/.../indexes?create_composite=...
#         链接，Console 会预填好索引，点「创建」即可
```

索引构建需 1–3 分钟（Console 状态「构建中」→「已启用」）。建好后 app 监听会自动
重连拉到新数据；若没动静，重启一次 app 必好。

> 教训：新增任何「等值过滤 + 按另一字段排序」的客户端查询，都要同步在
> `firestore.indexes.json` 声明复合索引并部署，否则线上静默回落缓存。

## 六、其他注意事项

- 脚本写入**生产 Firestore**（`inkite-demo`），执行前确认 `--title` 和 `--words` 正确。
- 全集合约定同时只有 **1 条** `isActive=true`，脚本会自动处理旧条目，无需手动操作 Console。
- `--words` 中每个词不应含逗号，词语之间不留空格，如 `秋,霜,归`（对，）而非 `秋, 霜, 归`（错）。
- 若报 `PERMISSION_DENIED`，检查凭证文件是否正确，以及文件对应账号是否有 Firestore 写权限。
- 若报 `Unable to detect a Project Id`，说明未找到凭证。确认 adminsdk JSON 在 `functions/` 下，或用 `--creds` 指定。
- 若报 `14 UNAVAILABLE ... ETIMEDOUT`，是直连 Google 被墙，加 `--proxy`（见 §二）。
