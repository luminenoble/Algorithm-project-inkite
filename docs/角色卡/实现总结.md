## 2. 数据流

```
ISR-scraper (本地, 一次性)                Firestore (运行期, 只读)         Flutter app
─────────────────────────                ───────────────────────         ───────────
docker-compose up -d (ES+Mongo+Tika)
uvicorn api.main:app --port 8000
python jobs/export_characters.py  ──►  seed/characters_input.json
                                          │
node scripts/import_characters.mjs ◄──────┘
  GET /search/cards?q=<name>               聚合
  GET /doc/{doc_id}            ───────►  charactersCache/{characterKey}  ──►  ExploreScreen
                                          (Admin SDK 绕规则写)               searchByName / listPopular
                                                                            CharacterDetailScreen
                                                                            watchByKey
```

## 3. 字段映射（ISR `HitCard`/`DocDetail` → `CharacterCache`）

| CharacterCache | ISR 来源 | 脚本处理 |
|---|---|---|
| `name` | 清单输入 | trim，保留原大小写 |
| `characterKey`（doc id） | normalize(name) | 小写 + 去标点 + 空白→单下划线，`"Hu Tao"→hu_tao` |
| `wikiSummary` | 主条目 `HitCard.snippet_plain` | 空则回退 `DocDetail.body` 截断 `--summary-max`(默认 800) |
| `wikiUrl` | 主条目 `DocDetail.url` | 经 `/doc/{doc_id}` 补 |
| `source` / `tag` | 主条目 `HitCard.source` / `.tag` | 小写 |
| `redditPosts[]` | reddit/ao3 hits 前 `--reddit`(默认 5) 项 | `{title, url(补/doc), snippet, source, tag}` |
| `popularity` / `obscurity` | 主条目 `DocDetail.popularity` / `.obscurity` | Number 化，缺省 0 |
| `searchTokens` | name | 整名(含空格)累进前缀 + 各分词累进前缀，上限 12，去重 |
| `cachedAt` | — | `FieldValue.serverTimestamp()` |

**主条目挑选**（脚本 `buildCharacterDoc`）：hits 中优先
`source∈{wikipedia,fandom} 且 tag=canon`；回退任意 `wikipedia/fandom`；再回退首条。

## 4. 设计取舍

- **无全文索引**：app 端用 `searchTokens` 数组 `array-contains` 做前缀近似，牺牲
  BM25/语义排序（ISR 的强项）。落地默认列表按 `popularity` 降序。demo 足够；
  要恢复完整检索体验须走方案 B/C（托管 FastAPI），本任务不含。
- **不需复合索引**：`searchByName` 单字段 `array-contains`、`listPopular` 单字段
  `orderBy` 均不触发复合索引；`firestore.indexes.json` 不动。
- **未改 `firestore.rules`**：`charactersCache` 段已是 `read: isSignedIn / write: false`，
  导入用 Admin SDK 绕规则，client 端零写操作。
- **per-token 前缀**：todo §2 只要求整名前缀 + 完整 token，本实现额外对每个分词也
  生成累进前缀，使 `"tao"`/`"ta"` 也能召回 `"Hu Tao"`，体验更好，数组开销仍可控。
