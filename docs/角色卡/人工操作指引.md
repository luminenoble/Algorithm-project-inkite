# 「开拓」栏人工操作指引

> 涉及 ISR 后端、Windows 构建、Firestore 写入的步骤须本机执行（Claude 不代跑）。
> 关键约束：**不从 WSL 跑 flutter**（共享盘 plugin symlink 会让 Windows 构建崩），
> Flutter 命令一律在 Windows 侧执行。

## A. 前端依赖（Windows，一次）

新增了 `url_launcher`。在 **Windows** 的 `app-storage/` 下：

```powershell
flutter pub get
```

（不要 `flutter clean`——见根 memory：clean 会触发 806MB Firebase SDK zip 重下被截断。）

跑通验证：

```powershell
flutter run -d windows
```

进底栏「开拓」：即使 `charactersCache` 为空也应优雅降级（显示「角色库还空着」空态）。

## B. 导入角色卡（一次性离线）

### B.1 ISR-scraper 侧起后端（WSL 路径 `../ISR-scraper`）

```bash
cd ../ISR-scraper
docker-compose up -d                 # ES + Mongo + Tika
source .venv/bin/activate
uvicorn api.main:app --port 8000     # FastAPI
curl http://localhost:8000/health    # 确认 ok:true、doc_count>0
```

### B.2 导出角色清单

```bash
# 仍在 ISR-scraper 根、.venv 激活
python jobs/export_characters.py --top 3000
# 输出默认落到 ../Algorithm/functions/scripts/seed/characters_input.json
# 硬性条件：原神角色 > 100，否则非零退出并提示补抓（见脚本头注释）
```

### B.3 先在 Firestore Emulator 验证（零成本，强烈建议）

```bash
# 终端 1：在 Algorithm 仓根起 emulator
firebase emulators:start --only firestore

# 终端 2：在 functions/ 下 dry-run 看聚合是否正常（不写任何库）
cd functions
node scripts/import_characters.mjs --dry-run --limit 20

# 再写入 emulator
node scripts/import_characters.mjs --emulator
```

### B.4 写线上 `inkite-demo`

确认 Emulator 结果无误后，准备 service account JSON（`*adminsdk*.json` 放 `functions/`，
已被 `.gitignore` 忽略，**绝不入仓**），国内网络需挂代理：

```bash
cd functions
node scripts/import_characters.mjs --proxy http://127.0.0.1:7890
```

常用参数：`--input <path>`、`--isr <url>`、`--size <n>`（每名取 hits 数，默认 8）、
`--reddit <n>`（民间二创条数，默认 5）、`--limit <n>`（只导前 n 名，调试用）、
`--summary-max <n>`（摘要截断，默认 800）。
